## ✅ ПАТТЕРНЫ, КОТОРЫЕ ВЫ УЖЕ ИСПОЛЬЗУЕТЕ

### 1. **Service Locator** ⭐ (используется)
```csharp
// ВЫ ТАК ДЕЛАЕТЕ:
private InventoryController inventoryController;

private void Start()
{
	inventoryController = FindAnyObjectByType<InventoryController>();
}
```

**Что это:**
- Находит и получает доступ к сервисам (контроллерам) из любого места кода
- Плюсы: просто, удобно, подходит для Unity
- Минусы: сложно тестировать, есть скрытые зависимости

**Оценка:** 7/10 для прототипов, 4/10 для продакшена. **Для учебного проекта - ОК!**

### 2. **Factory Pattern** ⭐ (используется частично)
```csharp
// ItemDictionary - это фактория для предметов
public GameObject GetItemPrefabByID(int itemID)
{
	// Возвращает нужный префаб по ID
}

// Использование:
GameObject itemPrefab = itemDictionary.GetItemPrefabByID(savedData.itemID);
```

**Что это:**
- Создаёт объекты (предметы) по определённым правилам
- Централизованное место для создания
- Плюсы: легко менять логику создания, переиспользуемо
- Минусы: добавляет слой абстракции

**Оценка:** 9/10. **ХОРОШИЙ паттерн, держите его!**

## 🚀 КАКИЕ ПАТТЕРНЫ ДОБАВИТЬ (для улучшения)

### 1. **Observer/Event Pattern** - РЕКОМЕНДУЕТСЯ
```csharp
// Модифицированный InventoryController:
public class InventoryController : MonoBehaviour
{
	// События, на которые могут подписаться другие системы
	public event System.Action<Item> OnItemAdded;
	public event System.Action<Item> OnItemRemoved;
	public event System.Action OnInventoryFull;

	public bool AddItemToInventory(GameObject itemPrefab)
	{
		foreach (Transform slotTransform in inventoryPanel.transform)
		{
			InentorySlot slot = slotTransform.GetComponent<InentorySlot>();
			if (slot.currentItem == null)
			{
				GameObject newItem = Instantiate(itemPrefab, slot.transform);
				slot.currentItem = newItem;

				// НОВОЕ: Оповещаем всех слушателей
				Item item = newItem.GetComponent<Item>();
				OnItemAdded?.Invoke(item);
				return true;
			}
		}

		// Все слоты заполнены
		OnInventoryFull?.Invoke();
		return false;
	}
}

// Где-то в другом классе можно слушать:
public class SoundManager : MonoBehaviour
{
	private void Start()
	{
		InventoryController inv = FindAnyObjectByType<InventoryController>();
		inv.OnItemAdded += PlayItemAddSound;
	}

	private void PlayItemAddSound(Item item)
	{
		// Проигрываем звук
	}
}
```

**Плюсы:**
- Слабая связанность между компонентами
- Легко добавлять новые реакции (звуки, UI, логика)
- Профессиональный подход

**Когда применять:** Когда одно действие вызывает реакции в разных системах

### 2. **Strategy Pattern** - ПОЛЕЗНО
```csharp
// Интерфейс для разных стратегий сохранения
public interface ISaveStrategy
{
	void Save(SaveData data, string path);
	SaveData Load(string path);
}

// Сохранение в JSON (текущее)
public class JsonSaveStrategy : ISaveStrategy
{
	public void Save(SaveData data, string path)
	{
		File.WriteAllText(path, JsonUtility.ToJson(data));
	}

	public SaveData Load(string path)
	{
		return JsonUtility.FromJson<SaveData>(File.ReadAllText(path));
	}
}

// Возможно будущее: сохранение в Binary или Cloud
public class CloudSaveStrategy : ISaveStrategy
{
	public void Save(SaveData data, string path)
	{
		// Отправить на облачный сервер
	}

	public SaveData Load(string path)
	{
		// Загрузить с облачного сервера
	}
}

// SaveController использует стратегию:
public class SaveController : MonoBehaviour
{
	private ISaveStrategy saveStrategy;

	private void Start()
	{
		// Выбираем стратегию
		saveStrategy = new JsonSaveStrategy();
		// Или: saveStrategy = new CloudSaveStrategy();
	}

	public void SaveGame()
	{
		saveStrategy.Save(saveData, saveLocation);
	}
}
```

**Когда применять:** Когда есть несколько способов делать одно и то же

### 3. **Dependency Injection (DI)** - ПРОДВИНУТАЯ ТЕХНИКА
```csharp
// Вместо FindAnyObjectByType, передаём зависимости через конструктор
public class InventoryController : MonoBehaviour
{
	private ItemDictionary itemDictionary;

	// Вместо: private void Start() { itemDictionary = FindAnyObjectByType<...>(); }
	// Передаём в конструктор:
	public InventoryController(ItemDictionary dictionary)
	{
		itemDictionary = dictionary;
	}
}
```

**Плюсы:** Легко тестировать, явные зависимости  
**Минусы:** В Unity сложнее настроить  
**Оценка:** 8/10 для продакшена, 5/10 для прототипов. **Сейчас не нужно, но знайте о нём**

## 🧪 UNIT-ТЕСТЫ: ПОЛНЫЙ ГАЙДЛАЙН

### ЧТО ЭТО?

**Unit-тест** - это маленькая программа, которая проверяет, работает ли ваш код правильно.

```csharp
// Пример простого unit-теста:
[Test]
public void AddItem_WhenSlotIsEmpty_ShouldReturnTrue()
{
	// Arrange (подготовка): создаём тестовые данные
	InventoryController inventory = new InventoryController();
	GameObject itemPrefab = new GameObject("TestItem");

	// Act (действие): делаем то, что тестируем
	bool result = inventory.AddItemToInventory(itemPrefab);

	// Assert (проверка): убеждаемся в результате
	Assert.IsTrue(result, "Предмет должен был добавиться в пустой слот");
}
```

---

### СМЫСЛ UNIT-ТЕСТОВ

| Плюсы | Минусы |
|-------|--------|
| ✅ Ловят баги до продакшена | ❌ Требуют времени на написание |
| ✅ Документируют код | ❌ Нужно поддерживать при изменениях |
| ✅ Дают уверенность при рефакторинге | ❌ Не ловят все ошибки |
| ✅ Ускоряют разработку (на длинную дистанцию) | ❌ Не нужны для UI-анимаций |

---

### НАДО ЛИ ПИСАТЬ ТЕСТЫ НА УЧЕБНЫХ ПРОЕКТАХ?

**ОТВЕТ: ДА, АБСОЛЮТНО!** Вот почему:

1. **Для портфолио** 🎯
   - Работодатели видят: "Чел пишет тесты = профессионал"
   - +500 очков при собеседовании

2. **Для практики** 💪
   - Это обязательный навык для Junior/Mid разработчика
   - На реальной работе будут требовать 80%+ покрытие кода

3. **Для уверенности** 🛡️
   - Можешь рефакторить код, не боясь всё сломать
   - Тесты скажут "Всё сломалось!"

4. **Для архитектуры** 🏗️
   - Пока пишешь тесты, видишь проблемы дизайна кода
   - Заставляет писать чище и разделять ответственность

---

### КОГДА ПИСАТЬ ТЕСТЫ

| ЧТО | ПИСАТЬ? | ПОЧЕМУ |
|-----|---------|--------|
| **Логика сохранения/загрузки** | ✅ ОБЯЗАТЕЛЬНО | Критическая функция |
| **Логика инвентаря** | ✅ ДА | Сложная логика, легко сломать |
| **Калькуляции урона, XP, деньги** | ✅ ДА | Баги здесь дорогие |
| **UI анимации** | ❌ НЕТ | Невозможно тестировать просто |
| **Визуальные эффекты** | ❌ НЕТ | Требуют ручной проверки |
| **Звуки** | ❌ НЕТ | Требуют ушей 👂 |

### ПРИМЕР: ПИШЕМ ТЕСТЫ ДЛЯ ВАШЕГО КОДА

```csharp
using NUnit.Framework;
using UnityEngine;
using System.Collections.Generic;

[TestFixture]
public class InventoryControllerTests
{
	private InventoryController inventoryController;
	private GameObject inventoryPanel;
	private GameObject inventorySlotPrefab;

	[SetUp] // Выполняется перед каждым тестом
	public void Setup()
	{
		// Создаём тестовый инвентарь
		inventoryPanel = new GameObject("TestPanel");
		inventorySlotPrefab = new GameObject("TestSlot");

		inventoryController = new InventoryController();
		inventoryController.inventoryPanel = inventoryPanel;
		inventoryController.inventorySlotPrefab = inventorySlotPrefab;
	}

	[TearDown] // Выполняется после каждого теста
	public void Teardown()
	{
		Object.DestroyImmediate(inventoryPanel);
		Object.DestroyImmediate(inventorySlotPrefab);
	}

	// ТЕСТ 1: Добавление предмета в пустой инвентарь
	[Test]
	public void AddItemToInventory_WithEmptySlot_ReturnsTrue()
	{
		// Arrange
		GameObject itemPrefab = new GameObject("Sword");

		// Act
		bool result = inventoryController.AddItemToInventory(itemPrefab);

		// Assert
		Assert.IsTrue(result, "Должно вернуть true при добавлении в пустой слот");
	}

	// ТЕСТ 2: Попытка добавить предмет в полный инвентарь
	[Test]
	public void AddItemToInventory_WithFullSlots_ReturnsFalse()
	{
		// Arrange: заполняем все 21 слот
		for (int i = 0; i < 21; i++)
		{
			GameObject slot = Instantiate(inventorySlotPrefab, inventoryPanel.transform);
			slot.AddComponent<InentorySlot>();
		}

		// Act: пытаемся добавить 22-й предмет
		GameObject itemPrefab = new GameObject("ExtraItem");
		bool result = inventoryController.AddItemToInventory(itemPrefab);

		// Assert
		Assert.IsFalse(result, "Должно вернуть false при переполнении инвентаря");
	}

	// ТЕСТ 3: Сохранение и загрузка данных
	[Test]
	public void GetInventorySaveData_ReturnsCorrectItemID()
	{
		// Arrange
		GameObject itemPrefab = new GameObject("TestItem");
		Item itemComponent = itemPrefab.AddComponent<Item>();
		itemComponent.itemID = 42;

		inventoryController.AddItemToInventory(itemPrefab);

		// Act
		List<InventorySaveData> savedData = inventoryController.GetInventorySaveData();

		// Assert
		Assert.AreEqual(1, savedData.Count, "Должно быть одно сохранённое изделие");
		Assert.AreEqual(42, savedData[0].itemID, "ID предмета должен быть 42");
	}
}
```
